# GPUI vs Tauri for Trantor

Research snapshot: 2026-11-20. Recommendation: **stay on Tauri + React**; revisit GPUI only for a tightly scoped native-rendering experiment if a concrete performance or native-integration need appears. **[B]** The evidence is strongest for framework capabilities and weaker for predicting migration effort; estimates below are engineering judgments from the checked-in surface area, not measured schedules. **[B]**

## Evidence grades

- **A** — primary source: official project documentation, project source/manifests, or Trantor source at the base commit.
- **B** — inference from those primary sources, such as effort or suitability; explicitly an estimate rather than a measured result.
- **X** — unverified: the referenced source did not establish the claim, or a hands-on build/runtime check is still needed.

## Findings

### Maturity, stability, and license

- GPUI is Zed's hybrid immediate/retained, GPU-accelerated Rust UI framework, and its own README says it is actively developed, pre-1.0, and subject to breaking changes. **[A]** [GPUI README](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md)
- The GPUI crate manifest declares Apache-2.0; the GPUI Kit source and examples also declare Apache-2.0, while its documentation prose and illustrations have separate CC BY 4.0 terms. **[A]** [GPUI Cargo.toml](https://github.com/zed-industries/zed/blob/main/crates/gpui/Cargo.toml) · [GPUI Kit license notes](https://github.com/longbridge/gpui-kit#license)
- GPUI Kit is a third-party component library, not a Zed-maintained widget layer; its published component docs list common controls, text editors, dialogs, popovers, and tables. **[A]** [GPUI Kit](https://github.com/longbridge/gpui-kit) · [base control coverage](https://github.com/longbridge/gpui-kit/blob/main/crates/base/README.md)
- Trantor already has a Tauri 2 + React 19 + Vite app, Vitest, xterm.js, and Monaco dependencies, plus a Rust command layer; its Tauri config enables bundling for all targets and sets a CSP. **[A]** [Trantor package.json](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/package.json) · [Tauri config](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src-tauri/tauri.conf.json)
- Tauri's official docs support using an existing frontend framework and advertise macOS, Linux, and Windows among supported desktop targets. **[A]** [Tauri overview](https://v2.tauri.app/)
- **Unverified:** a comparative benchmark of Trantor rendered in GPUI versus the existing WebView was not found in the reviewed sources; no performance advantage is assumed here. **[X]**

### Platforms and delivery

- Current GPUI workspace docs describe macOS via Metal, Linux/FreeBSD with Wayland and/or X11, and Windows via Win32/DirectWrite. **[A]** [GPUI README platform notes](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md)
- Thus GPUI has code paths for all three desktop targets, but each platform still brings distinct dependencies and rendering/text backends; Linux builds must choose windowing features, and macOS builds require Xcode tooling. **[A]** [GPUI README](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md)
- Tauri already packages Trantor's app for all targets in its checked-in config; Tauri documents target-specific bundling and prerequisites. **[A]** [Trantor bundle config](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src-tauri/tauri.conf.json) · [Tauri distribution guide](https://v2.tauri.app/distribute/)
- **Unverified:** GPUI Kit's release artifacts and a production signing/notarization pipeline equivalent to Trantor's current Tauri releases were not evaluated. **[X]** A full migration would need this release engineering work, not just a UI port. **[B]**

### Widget and terminal fit

- GPUI core supplies entities, views, elements, layout, styling, keyboard actions, and custom rendering primitives; its README positions low-level elements as suitable for efficient large lists and editor-like custom layout. **[A]** [GPUI README](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md)
- GPUI Kit documents buttons, checkboxes, radios, switches, links, tables, single- and multiline text controls, and a source editor with highlighting, folding, decorations, diagnostics, and LSP integration. **[A]** [GPUI Kit controls](https://github.com/longbridge/gpui-kit/blob/main/crates/base/README.md)
- GPUI Kit's documented component set includes Dialog, Sheet, Popover, Select, Combobox, and related overlays. **[A]** [GPUI Kit architecture](https://github.com/longbridge/gpui-kit/blob/main/docs/ARCHITECTURE.md)
- GPUI Kit documents IME-aware text editing, and GPUI's platform input handler has IME-specific composition behavior; that establishes implementation support but does not prove equivalent behavior for Trantor's text workflows across all operating systems. **[A/X]** [GPUI Kit Input](https://github.com/longbridge/gpui-kit/blob/main/website/base/primitives/input.md) · [GPUI platform text input](https://github.com/zed-industries/zed/blob/main/crates/gpui/src/platform.rs)
- That is enough raw capability to recreate Trantor's chat, lists, graph cards, popovers, and forms, but matching Trantor's styling, keyboard behavior, saved state, and tested edge cases remains application work. **[B]** [Trantor chat composer](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/chat/Composer.tsx) · [graph view](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/code/GraphView.tsx)
- Trantor's terminal surface is xterm.js hosted in a WebView and connected to herdr through attach/write/resize/detach operations; the Rust side manages terminal sessions. **[A]** [TerminalPane](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/workspace/TerminalPane.tsx) · [herdr bridge](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/workspace/herdr.ts) · [Rust terminal](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src-tauri/src/terminal.rs)
- Zed's terminal crate is a substantial integration: it uses `alacritty_terminal` and GPUI types together, so it is not a drop-in GPUI widget or a small standalone terminal crate. **[A]** [Zed terminal source](https://github.com/zed-industries/zed/blob/main/crates/terminal/src/terminal.rs)
- Reusing Zed terminal code would require adapting its internal crate dependencies, process/session model, rendering, clipboard/input, and Trantor's herdr protocol; retaining xterm.js inside a GPUI-hosted webview would also preserve a web runtime and reduce the reason to migrate that surface. **[B]** [Zed terminal crate](https://github.com/zed-industries/zed/tree/main/crates/terminal) · [Trantor herdr bridge](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/workspace/herdr.ts)
- **Unverified:** no public compatibility guarantee or independently packaged terminal crate for Zed's GPUI terminal was found. **[X]** Treat direct reuse as requiring a prototype and dependency/license audit.

### Testing and accessibility

- GPUI documents a `gpui::test` macro, a `TestAppContext`, and simulated common platform input; its platform source also notes some visual tests are ignored by default because they require the macOS main thread. **[A]** [GPUI README testing notes](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md) · [platform test notes](https://github.com/zed-industries/zed/blob/main/crates/gpui_platform/src/gpui_platform.rs)
- Trantor has Vitest configured and existing per-surface tests such as `TerminalPane.test.tsx` and graph lens tests; porting means replacing React Testing Library/DOM assumptions with Rust test fixtures and rebuilding those behavioral tests. **[A/B]** [Trantor package.json](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/package.json) · [terminal tests](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/workspace/TerminalPane.test.tsx) · [graph tests](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/code/graph/GraphLens.test.tsx)
- GPUI integrates AccessKit for programmatic accessibility, but its guide requires apps/elements to expose semantics and respond to assistive-technology actions. **[A]** [GPUI accessibility guide](https://github.com/zed-industries/zed/blob/main/crates/gpui/src/_accessibility.rs) · [GPUI element accessibility hooks](https://github.com/zed-industries/zed/blob/main/crates/gpui/src/element.rs)
- GPUI Kit adds accessibility roles to documented controls, but this does not establish parity for Trantor's complete app or actual screen-reader behavior on each OS. **[A/X]** [GPUI Kit controls](https://github.com/longbridge/gpui-kit/blob/main/crates/base/README.md); **unverified:** end-to-end VoiceOver, NVDA, and Orca checks for our proposed port.
- Trantor's current React surfaces use HTML controls and explicit ARIA patterns, while Tauri embeds a WebView; the actual accessibility quality is still an app-level property and should be tested with assistive technology. **[A/B]** [Composer](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/chat/Composer.tsx) · [graph lens](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/code/graph/GraphLens.tsx)

## Per-surface migration estimate

These are relative engineering estimates for one experienced Rust/GPUI engineer, assuming the current backend commands and product behavior remain required. They include UI, interaction parity, and test replacement; they are **not** measured or committed schedule. **[B]**

| Surface | Estimate | Why |
|---|---:|---|
| Terminal pane | **High: 4–8 engineer-weeks** | Replace xterm renderer/addons, preserve resize/input/selection behavior and herdr streaming, or adapt Zed's coupled terminal crate. **[B]** [TerminalPane](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/workspace/TerminalPane.tsx) · [Zed terminal](https://github.com/zed-industries/zed/blob/main/crates/terminal/src/terminal.rs) |
| Chat and composer | **High: 4–7 engineer-weeks** | Streaming transcript, markdown, attachments, draft persistence, handoff states, keyboard and accessibility behaviors all need Rust equivalents and tests. **[B]** [Chat](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/chat/Chat.tsx) · [Composer](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/chat/Composer.tsx) |
| Graph lens | **Medium-high: 3–6 engineer-weeks** | Port graph layout, pan/zoom/selection, graph state, SVG/canvas rendering, tooltips and file-opening integration; test dimensions and interaction parity. **[B]** [GraphView](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/code/GraphView.tsx) · [GraphLens](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features/code/graph/GraphLens.tsx) |
| Workspace, board, feed, bus, settings, onboarding, popovers | **High: 8–14 engineer-weeks** | Broad React surface and state/event wiring; GPUI Kit covers common controls, but product-specific flows and cross-surface state still need bespoke Rust views. **[B]** [feature tree](https://github.com/sashabogi/trantor/tree/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src/features) · [GPUI Kit controls](https://github.com/longbridge/gpui-kit/blob/main/crates/base/README.md) |
| App shell, native commands, packaging, accessibility and release parity | **High: 4–8 engineer-weeks** | Keep or redesign the Tauri command/IPC boundary, CSP/security model, notifications/deep links, target packaging, and assistive-technology checks. **[B]** [Tauri config](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src-tauri/tauri.conf.json) · [Tauri security docs](https://v2.tauri.app/security/) · [Tauri distribution](https://v2.tauri.app/distribute/) |

**Total full-port order of magnitude: 23–43 engineer-weeks**, before feature development during the port, rollout, and unknowns from GPUI version churn. **[B]** Treat that as a planning range, not a quote; validate with a short spike before any migration decision.

## Recommendation

**Stay with Tauri + React. [B]** It already matches our implementation: browser-native forms and accessibility semantics, xterm.js terminal rendering, React-driven interaction, Vitest coverage, Rust commands, CSP, and configured cross-platform bundling. **[A]** [Trantor frontend dependencies](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/package.json) · [Tauri config](https://github.com/sashabogi/trantor/blob/d1ff43ad900da1dc43aa7baba8a43940b41747e4/desktop/src-tauri/tauri.conf.json) · [xterm.js](https://xtermjs.org/)

**Do not migrate now. [B]** GPUI can render the needed UI, but API churn, a framework/test rewrite, custom accessibility validation, packaging work, and especially terminal coupling outweigh any performance claim that has not been measured for this app. **[A/B]** [GPUI stability statement](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md) · [Zed terminal source](https://github.com/zed-industries/zed/blob/main/crates/terminal/src/terminal.rs)

**Hybrid is only justified by a measured need. [B]** If a future spike identifies one renderer-bound surface, prototype that surface behind a process boundary while retaining Tauri as the shell; avoid embedding two UI stacks without a concrete benchmark or native capability gap. **[B]** **Unverified:** GPUI hosting inside this Tauri application and its window/input/accessibility integration have not been demonstrated. **[X]**
