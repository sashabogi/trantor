# Hindsight assessment — #11669

**Recommendation: keep the current memory layers; borrow Hindsight's retrieval and evidence model before considering a Gaia backend replacement.** Hindsight addresses a real weakness in Gaia's installed search path: finding facts across paraphrases, entities and time. It does not replace Claude Code's startup index or Trantor's source-code freshness checks. Gaia checkpoints are also a different contract from generated recollections.

## What Hindsight actually provides

Hindsight is a memory service with **retain**, **recall** and **reflect** operations, organized by memory bank. Retain extracts structured facts using an LLM and embeds them; recall retrieves evidence; reflect runs a tool-using synthesis loop over stored knowledge. Facts distinguish world information from the agent's experiences; observations consolidate facts, and mental models provide curated or generated summaries. These are semantic categories, unlike Gaia's session/project/global storage tiers. Evidence: `H/README.md:277-303`, `H/hindsight-api-slim/hindsight_api/engine/retain/orchestrator.py:1281-1337`, and `H/hindsight-api-slim/hindsight_api/engine/reflect/agent.py:1-8`.

The recall pipeline gathers semantic, keyword, graph and temporal candidates, merges ranked lists, reranks, and applies output budgets. Rank fusion combines ranks rather than assuming unrelated raw scores share a scale. The implementation also has an interleaving option for consolidation deduplication, where a semantic near-duplicate must not disappear below the candidate cutoff. Evidence: `H/hindsight-api-slim/hindsight_api/engine/search/retrieval.py:114-222`, `H/hindsight-api-slim/hindsight_api/engine/search/fusion.py:29-109`, `H/hindsight-api-slim/hindsight_api/engine/search/fusion.py:112-129`, and `H/hindsight-api-slim/hindsight_api/engine/memory_engine.py:8795-8825`.

The standard deployment uses PostgreSQL with pgvector; embedded pg0 still runs PostgreSQL. A separate graph database is not required. The PostgreSQL retrieval source explicitly selects bank-scoped records with embeddings, document/chunk provenance and event timestamps (`H/hindsight-api-slim/hindsight_api/engine/memories/pg/recall.py:467-488`). Oracle is another documented deployment. The newly announced Memlake backend does not change the open-source default: its launch post explicitly retains PostgreSQL/Oracle for that purpose (`H/hindsight-docs/blog/2026-10-13-memlake.md:69-71`). Do not interpret the older storage page's “no abstraction” wording as current architecture: retrieval now delegates to a memory-store interface (`H/hindsight-api-slim/hindsight_api/engine/search/retrieval.py:124-128`).

REST exposes recall and reflect under bank URLs (`H/hindsight-api-slim/hindsight_api/api/http.py:6166`, `H/hindsight-api-slim/hindsight_api/api/http.py:6411`). The HTTP MCP implementation has multi-bank and bank-bound modes, an enabled-tool allowlist, and retains API-key/tenant context. Its surface includes retain/recall/reflect, memory and document operations, directives, mental models, operations and knowledge pages (`H/hindsight-api-slim/hindsight_api/api/mcp.py:114-198`). The local MCP entry point starts the API with embedded PostgreSQL; it is not a lightweight SQLite adapter (`H/hindsight-api-slim/hindsight_api/mcp_local.py:1-23`). Python, TypeScript and Go clients are documented in `H/README.md:121-164`.

Operational cost is materially above the current local memory path. The slim API already requires Python 3.11+, FastAPI/Uvicorn, asyncpg, SQLAlchemy/Alembic, pgvector, FastMCP and model-provider libraries. Local embedding/reranking extras add sentence-transformers, transformers and torch (`H/hindsight-api-slim/pyproject.toml:5-39`, `H/hindsight-api-slim/pyproject.toml:109-130`). Retain pays extraction and embedding costs; reflect adds generation; recall adds embedding, database and reranking work. Exact latency, RAM and dollar costs for our workload remain unmeasured. Self-hosting storage does not imply local inference; provider selection determines where text is processed.

The core is MIT licensed (`H/LICENSE:1-21`). The checkout declares version 1.0.0, has system/integration tests and evaluation tooling, and its changelog includes a bank-access breaking change (`H/hindsight-docs/src/pages/changelog/index.md:12-16`). That is evidence of a substantial maintained product, not evidence of compatibility with our memory semantics or operational reliability here. README production/reproduction statements are vendor claims, not findings of this assessment.

## Our stack, including concrete weaknesses

**Gaia is a local record store plus a workflow/checkpoint layer.** `MemoriaStorage` uses better-sqlite3 and WAL (`G/dist/tools/gaia/storage.js:7-32`), five tiers and FTS5 over content/tags/files (`G/dist/tools/gaia/storage.js:37-65`). Search takes FTS candidates, then weights relevance, recency, tier, file proximity and access frequency (`G/dist/tools/gaia/storage.js:213-286`). It also merges Memory Rescue results; it is not limited to a single physical source. Links already carry typed relations and validity intervals; `getLinks` supports an as-of cutoff (`G/dist/tools/gaia/storage.js:85-101`, `G/dist/tools/gaia/storage.js:291-356`).

There are three specific gaps worth fixing:

1. **Semantic search is not demonstrated on the installed Gaia route.** Foundation's wrapper README describes optional Open Brain/Supabase vector search and merged dual reads (`F/README.md:127-162`). But installed `gaia_search` directly calls `storage.search`, whose candidates are FTS matches (`G/dist/tools/gaia/index.js:964-978`, `G/dist/tools/gaia/storage.js:213-233`). The installed server registers Gaia, Demerzel and Provider (`G/dist/index.js:70-80`). This establishes a documentation/runtime mismatch for the inspected path; it does not establish whether the operator has another cloud-memory integration configured. Hindsight's semantic arm could retrieve paraphrases excluded before Gaia's rescoring even starts. Rank fusion alone cannot recover a fact absent from every candidate set.
2. **Project context does not enforce project isolation here.** `F/hooks/sessionstart.mjs:142-155` passes `project_path`, but `F/src/memory/gaia.mjs:42-46` forwards only tiers and limit; `G/dist/tools/gaia/storage.js:404-416` also has no project predicate. `gaia_search` accepts a project path but the local search SQL filters only tiers, and proximity scoring checks only the current file. Thus unrelated project memories can enter the startup list labeled as project memories. Hindsight supplies bank-scoped retrieval, but adopting it fixes this only if an adapter maps and binds the correct project bank. A small Gaia scoping fix is the more direct first action. No observed data leak is claimed; operator records were not read.
3. **The graph is separate from search.** Gaia's typed/as-of links are useful, but the inspected `search` does not expand graph neighbors. Hindsight combines those candidates with lexical/semantic/time retrieval and has consolidation with provenance. That is a meaningful capability gap for multi-session questions, not proof that its inferred relationships are correct.

Gaia's checkpoint tool persists `checkpoint.json`, an index and decisions, and archives the checkpoint (`G/dist/tools/gaia/index.js:131-185`). Its handoff operation combines this state with memories (`G/dist/tools/gaia/index.js:366-434`). A retained narrative plus generated reflection is not equivalent to preserving exact unfinished tasks, branch context and decisions.

**Claude Code auto-memory is the readable startup index.** Official documentation describes project-local Markdown with a `MEMORY.md` index and topic files. The first 200 lines or 25KB of the index, whichever comes first, enter startup context; topic files load on demand. That gives selected facts visibility without a service call, although entries outside the index budget and unselected topic files are not automatically present. Memory is machine-local; current documentation describes worktree sharing and configurable directories. We did not inspect actual saved notes or settings. This behavior is documented by [Anthropic, “Storage location” and “How it works”](https://code.claude.com/docs/en/memory#how-it-works), scratch capture lines 432-456.

**Trantor pins are a source freshness layer.** [T/lib/memory-pins.mjs:67-91](../../lib/memory-pins.mjs#L67) reports broken files/symbols or a changed normalized symbol-body fingerprint. A file-only pin checks existence, not body changes; an intact hash does not prove the note's prose is true. Without a graft graph the feature is off, and `MEMORY.md` is excluded ([T/lib/memory-pins.mjs:132-146](../../lib/memory-pins.mjs#L132)). The writer rejects attempts to pin the index and uses an atomic checked write ([T/lib/memory-pin-write.mjs:101-111](../../lib/memory-pin-write.mjs#L101), [T/lib/memory-pin-write.mjs:150-156](../../lib/memory-pin-write.mjs#L150)). Startup checking has a deadline and flags an older graph as unchecked ([T/hooks/lib/memory-start.mjs:6-28](../../hooks/lib/memory-start.mjs#L6), [T/hooks/lib/memory-start.mjs:44-62](../../hooks/lib/memory-start.mjs#L44)). Hindsight event time and updated observations do not fingerprint our current code.

One adjacent compatibility issue deserves a follow-up: Trantor derives the memory directory from a normalized checkout path (`T/lib/memory-pins.mjs:17-18`); current CC documentation supports directory overrides. Do not assume a new memory service will fix path discovery, or assume every current CC configuration is covered by pins.

|---|---|---|---|---|
| Exact local note retrieval | Gaia SQLite FTS5, tier/file/recency scoring | Keyword plus other arms | Gaia for a small local exact-match store with no model dependency | High for full replacement: service, import, backup/restore and tool adapter |
| Paraphrase and multi-hop recall | Installed Gaia search remains lexical; links require separate reads; optional Open Brain is described but not verified on this route | Semantic + keyword + graph + temporal, fusion/reranking | Hindsight has broader candidate generation; quality unmeasured here | Medium to borrow fusion/graph expansion; high to adopt extraction/embeddings and service |

## Verdict per component

- **Gaia search/store: KEEP; BORROW candidate fusion and provenance.** Start by correcting project filtering and verifying the actual Open Brain route. Then test lexical + semantic/graph candidates using rank fusion, explicit source IDs and source timestamps. Hindsight is a plausible future replacement for this backend, but current evidence does not justify moving durable records or changing tools. Keep exact source text retrievable alongside any extracted facts.
- **Gaia checkpoints and handoffs: KEEP.** Preserve their structured schema and exact archive. If Hindsight is later adopted, a checkpoint can be an additional retrieval document, not a substitute for authoritative workflow state.
- **Foundation Open Brain: conditional replacement candidate, not an immediate change.** If a working separate deployment is confirmed and a Hindsight trial succeeds, replace that semantic backend rather than accumulating another store. Current installed `gaia_search` does not prove Open Brain participation; mapping its real callers and data is a prerequisite. Do not remove it on a README inference.
- **CC auto-memory: KEEP.** Maintain a concise human-editable index for preferences, rules and pointers. Borrow evidence/source metadata for topic notes if useful; do not turn essential startup instructions into probabilistic recall results.
- **Trantor pins: KEEP.** Preserve deterministic stale/broken warnings and the `MEMORY.md` exclusion. A future recall adapter should expose pin status or withhold stale coding advice pending review. Hindsight's temporal reasoning is not a replacement for a current-source fingerprint.

## A concrete next decision, without migration

Authorize a separate synthetic-data trial only if this capability is worth the operational cost. Compare the existing Gaia path, Gaia with corrected project scope, and an isolated Hindsight bank using identical invented notes: paraphrases, exact symbol names, two projects with conflicting conventions, retracted decisions, time-qualified questions, and a changed source symbol. Preserve checkpoints and the CC index in every condition.

Measure retrieved source precision/recall, wrong-project hits, contradiction handling, stale-source warnings, output tokens, p50/p95 latency, ingestion cost, duplicate ingestion and delete/restore behavior. Hold corpus, queries, answer model and answer budget constant, and record every provider/version and backend setting. Judge retrieval separately from generated answers. Adopt only after an agreed quality/latency/cost threshold and zero wrong-project results on the isolation cases; no such threshold or performance result is invented here.

A later migration would need stable mappings for Gaia IDs, tiers, project paths, timestamps, related files and links; an explicit decision about global/shared records; preserved raw checkpoints; and a rollback export. Those requirements, plus pin-status propagation, are the implementation work a replacement entails. None was attempted in this research card.
