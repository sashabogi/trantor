# WIP #13923 — a seat that reuses an old name must not inherit that name's old assignments

## Findings (recon at base e00262f)

- The incident path: kickoff runs `KICKOFF` (bin/crew-runner.mjs:1394) whose RULES tell the seat
  "make relay_board with mine:true your FIRST call … work your newest one (#7763)". The mine view
  (mcp.mjs:388-401) filters ONLY by `assignee === SESSION` + OPEN_CARD_STATUSES — and SESSION is
  the per-host+project bus id (`codex-7:trantor`), which a reused seat name re-mints verbatim.
  That is how a fresh codex-7 picked up #12138 (assigned weeks ago, still in testing) at kickoff.
- Exactly TWO production surfaces pick "my cards": mcp.mjs:394 (relay_board mine) and
  bin/crew-runner.mjs:1515 (`newestOwnCard` — the message-card reroute in `resolveWakeCard`).
  Both already share OPEN_CARD_STATUSES from lib/turn-policy.mjs "so the set lives in the one
  file both sides already import" — the instance fence belongs there too.
- No per-instance stamp exists anywhere: hub peer rows survive restarts (touch() only bumps
  lastSeen), and mcp.mjs's BOOT_TS is per-MCP-process (per turn), not per seat instance.
  The runner is the only place that knows the seat instance's start; it can stamp it into the
  turn shell env (`TRANTOR_SEAT_BOOT_TS`), which the CLI's MCP server inherits.
- "Contracted to it after it started" is checkable from the hub: a DIRECT message (to === session,
  not wake:false, not kind:status — the same demotions shouldWake applies) whose text cites #id.
  /inbox?since=0&peek=1 returns every retained deliverable message with ts (seedCursor precedent).
- Release restarts (CREW_RELEASE_STATE) are the same runner continuing: bootTs must ride
  releaseState; a swap (CREW_SWAP_STAGE) or fresh `trantor up` is a new instance.
- Assignment-time evidence: a card created after boot has `ts >= bootTs` (assignment can't predate
  creation). `updated` is WRONG as the fence (any post-boot touch — e.g. the orchestrator
  reverting the failed move in the incident — would re-activate the card). Re-contracts are
  covered by the direct-citation clause instead.
- Blast radius in tests: test/board/test-relay-mine.mjs (no stamp in env → fail open, unchanged);
  test/runner/test-wake-card-binding.mjs drill 2c reroutes to card 7701 which has NO ts → under
  the fence its wake text must cite #7701 (a message-card transcript cites the card it contracted);
  test-stale-card-binding's mock hub has no /tasks so newestOwnCard returns 0 both sides of the fix.
